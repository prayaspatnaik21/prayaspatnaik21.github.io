## CUDA Chapter 4 - Computer Architecture and Scheduling

### Architecture of a modern GPU

1. GPU is organized into an array of highly threaded streaming Multiprocessors (SMs).
2. Each SM has several processing units called streaming processors that share control logic and memory resources.
3. The memory resources of SMs consist of different on chip memory structures collectively labeled as Memory.

### Thread Block Scheduling

1. Thread Block Scheduling mechanisms is needed to assign threads to execution resources as the resource become available.
2. In CUDA , threads are assigned to SMs on a block by block basis.
3. Threads in a block are simultaneously assigned to the same SM.
4. Multiple blocks can be simultaneously assigned to the same SM as permitted by the available SM resources.
5. Blocks need to reserve hardware resources to execute, so only a limited number of blocks can be simultaneously assigned to a given SM.
6. Assignment of threads to SMs on a block by block basis guarantees that threads in the same block execute on the same SM and at the same time.
7. Guarantees makes it possible for threads in the same block to interact with each other in ways that thread across different blocks cannot.
8. Thread block cluster -> Group of thread blocks. Blocks in the same thread block cluster are co-scheduled onto the same GPC.
9. Threads in the smae cluster can synchronize via a corresponding API. Access to distributed  shared memory.
10. Distributed Shared Memory -> composed of the shared memory of all blocks participated in a thread block cluster. GPCs referred to as group of SMs (Streaming Multiprocessors)

### Synchronization and Transparent Scalability

1. CUDA allows threads in the same block to coordinate their activities using the block wide level barrier synchronization function.
2. When a thread calls __synthreads() , it will be held at the program location of the call until every thread in the same block reaches that location.
3. A thread that calls a synchronization function is said to arrive at the barrier that corresponds to the program location.
4. Barrier ensures that all the threads in a block have completed a phase of their execution before any of them can move onto the next phase.
5. When all threads arrive at the barrier , These threads are released from the barrier, which allows them to execute beyond the barrier's program location.
6. Thread block cluster level synchronization - All the threads in the same thread block cluster have arrived at the barrier and all of their distributed shared memory operations are completed before they can be released from the barrier.
7. Collection of threads involved in a barrier is called scope of the barrier.
8. At a grid level , threads across the entire grid can perform a grid wide barrier synchronization also through the Cooperative groups API.
9. Barrier Synchronization is basically co-ordinating parallel activities. Imposes execution constraints on threads within it scope.CUDA allows threads in the same block to coordinate their activities using the block wide synchronization function __syncthreads().
10. Barrier Synchronization imposes execution constraints on threads within its scope.
    1. Threads should execute in close proximity with each other to avoid execessively long waiting times.
    2. All the necessary resources to available for all the threads in a block.
    3. CUDA run time system satisfies this constraint by assigning execution resources to all the threads in a block as a unit.
    4. All the threads in a block should be assigned to the same SM.
11. Block can begin execution when the cuda run time provides all the resources to the thread (all) in the block to complete execution.
12. This ensures the time proximity of all threads in a block and prevent excessive or even indefinite waiting time during barrier synchronization.
13. A group of thread blocks executing simultaneously is called wave.
14. Number of waves = Total number of thread blocks in the grid / No. of blocks that can execute simultaneously.
15. Configure the numberof blocks in a grid as a multiple of the no. of blocks that can run simulataneously. No. of blocks that can run simultaneously depends on hardware resources available in the GPU.

### Warps and SIMD hardware

1. We can assume that threads in a block can execute in any order wrt to each other.
2. Thread Scheduling in CUDA GPUs is a hardware implementation concept.
3. Blocks are assigned to streaming Multiprocessor. It is further divided into 32 threads unit called warps. The size of warp is implementation specific.
4. A warp is a unit of thread scheduling in SMs.
5. Blocks are partitioned into warps based on thread indices.
6. nth Warp start with thread 32nth  and end width (32 (n + 1) - 1)th thread.For blocks whose size is not multiple of 32 , the last warp will be padded with inactive threads to fill up the 32 thread positions.
7. For Multidimensional blocks , the threads are laid out in row major format and it starts from x-axis threads whose y , z components are later considered.
8. Example
    1. 8 * 8 threads -> 64 threads
    2. 1 warp -> 32 threads -> 64 threads -> 2 warps
    3. (0,0) -> 1st thread in the 1st warp.
    4. what is the starting index of thread in the 2nd warp?
        1. each row contains 8 threads , therefore 4 rows would contain 32 threads.
        2. Last thread's index in the 1st warp is (3,7).
        3. Starting index of the first thread in the second warp is (4,0) and goes till (7,7)
9. 3D Example
    1. 2 * 8 * 4 block.
    2. The core understanding of the layout of the threads is as follows:
        1. (0 , 0 , 0) - (x , y , z)
        2. (0 , 0 , 1)
        3. (0 , 0 , 2)
        4. we will keep filling the threads in the zth axis and once we are done we start with y - axis and then x-axis.
        5. from the example , for each index in x-axis , there are 32 threads (combined y and z axis , 8 * 4)
        6. The last thread's index in the first warp would be (0 , 7 , 3). (Zero based indexing , remember !!!)
        7. Ist thread in the second warp is (1 , 0 , 0) -> (1 , 7 , 3)
10. An Streaming Multiprocessor is designed to execute all threads in a warp following the SIMD model.At any instant in time , one instruction is fetched and executed by all threads in a warp.
11. An SM is organized into multiple processing blocks and the warps on an SM are distributed across the processing blocks.SMs consist of processing blocks and every processing blocks consist of streaming processors with a shared instruction fetch/dispatch unit.
12. Threads in the same warp are assigned to the same processing block which fetches the instruction for the warp and executes it for all the threads in the warp.
13. These threads apply the same instruction to their portion of the data.
14. CUDA Scheduling mechanisms map warp to processing blocks and restricts all threads in a warp to execute the same instruction at any point in time.

### Control Divergence

1. When the thread in the same warp follow different control flow path , we say that these threads exhibit control divergence.
2. Multipass approach to divergent warp execution extends the SIMD hardware's ability to implement the full semantics of CUDA threads.
3. Hardware executes the same instruction for all threads in warp and selectively let these threads take affect in only the pass that corresponds to the path they took, allowing threads to take its own control path.
4. Cost of Divergence - Extra pass the hardware needs to take in order to allow different threads in a warp to make their own decisions as well as execution resources that are consumed by the inactive threads in each pass.
5. Architecture till pascal - Passes are executed sequentially. One pass is executed to completion followed by the other pass.
6. Volta Architecture - Passed may be executed concurently , execution of one pass may be interleaved with the execution of another pass. Independent Thread Scheduling.
7. One cannot assume that the threads of the warp reconverge after the divergent execution paths are executed.
8. If all the threads in a warp must complete a phase of their execution before any of them can move on, one must use a warp level barrier synchronization.
9. Control construct with thread control divergence is important for handling boundary conditions when mapping threads to data. The kernel need to add some quality check statement to make sure that we process only active threads not inactive threads.
10. Performance impact of control divergence decreases as size of data increases.

### Warp Scheduling

1. Threads are assigned to SMs , usually more threads are assigned to SM than streaming processors in the SM.
2. Earlier GPU Designs, each SM can execute only 1 instruction for a single warp at any given instant.
3. Recent Design , each SM can execute instructions for a small number of warp at any given instant of time.
4. Why do we need so many warps assigned to an SM if it can only execute a subset of them at any instant? -  This is how GPUs tolerate long latency operations such as Global memory accesses.
5. Instruction to be executed by a warp needs to wait for the result of a previously initiated long latency operation . The warp not selected for execution.
6. Instead another resident warp that is no longer waiting for the results of previous instructions will be selected for the execution.
7. If more than  two warps are ready , then priority logic is used , to select one for selection.
8. The ability for each SM to select different ready Warps for execution at each instant is called fine grained multithreading and allows SMs to use the latency time of instruction from some threads to execute instructions from other threads.
9. The selection of warps ready for execution does not introduce any idle or wasted time into the execution of timeline . (Zero overhead thread scheduling)
10. GPU SMs achieve zero overhead thread Scheduling by holding all the execution states for the assigned warps in the hardware registers so there is no need to save and restore states when switching from one warp to another.

### Resource Partitioning and Occupancy

1. The ratio of the number of warps assigned to SM to the maximum number of it supports is referred to as occupancy.
2. Execution resources in SM -> registers , shared memory , Thread block slots and thread slots.
3. Dynamically partitioned across threads to support their execution.
4. Fixed Partitioning results in wasted thread slots when each block demands fewer threads than the fixed thread supports.
5. Dynamically partitioning registers in an SM across threads. The SM can accomodate many blocks if they require few registers per thread and fewer blocks if they require more registers per thread.
6. Compiler may perform register spilling to reduce the register requirement per thread and thus elevate the level of occupancy. At the cost of execution time for the threads.
7. Performance Cliff -> Slight increase in resource usage can result in significant reduction in parallelism.
8. The amount of resource in each CUDA Device SM is specified as a part of the compute capability of the device.

#### Answer
{: .exercise-answer-heading}

    1. Every thread in the block reaches the barrier before any thread continues.
    2. Memory Operations performed before the barrier becomes visible to other threads in the block.
