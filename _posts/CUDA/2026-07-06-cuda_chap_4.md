2. Thread Block Scheduling

    1. Thread Block Scheduling mechanisms is needed to assign threads to execution resources as the resource become available.
    2. In CUDA , threads are assigned to SMs on a block by block basis.
    3. Threads in a block are simultaneously assigned to the same SM.
    4. Multiple blocks can be simultaneously assigned to the same SM as permitted by the available SM resources.
    5. Blocks need to reserve hardware resources to execute, so only a limited number of blocks can be simultaneously assigned to a given SM.
    6. Assignment of threads to SMs on a block by block basis guarantees that threads in the same block execute on the same SM and at the same time.
    7. Guarantees makes it possible for threads in the same block to interact with each other in ways that thread across different blocks cannot.
    8. Thread block cluster -> Group of thread blocks. Blocks in the same thread block cluster are co-scheduled onto the same GPC. 
    9. Threads in the smae cluster can synchronize via a corresponding API. Access to distributed  shared memory.
    10. Distributed Shared Memory -> composed of the shared memory of all blocks participated in a thread block cluster. GPCs referred to as group of SMs (Streaming Multiprocessors)

3. Synchronization and Transparent Scalability

    1. CUDA allows threads in the same block to coordinate their activities using the block wide level barrier synchronization function.

    3. When a thread calls __synthreads() , it will be held at the program location of the call until every thread in the same block reaches that location.
    4. A thread that calls a synchronization function is said to arrive at the barrier that corresponds to the program location. 
    5. Barrier ensures that all the threads in a block have completed a phase of their execution before any of them can move onto the next phase.
    6. When all threads arrive at the barrier , These threads are released from the barrier, which allows them to execute beyond the barrier's program location.
    7. Thread block cluster level synchronization - All the threads in the same thread block cluster have arrived at the barrier and all of their distributed shared memory operations are completed before they can be released from the barrier.
    8. Collection of threads involved in a barrier is called scope of the barrier.
    9. At a grid level , threads across the entire grid can perform a grid wide barrier synchronization also through the Cooperative groups API.
    10. Barrier Synchronization is basically co-ordinating parallel activities. Imposes execution constraints on threads within it scope.CUDA allows threads in the same block to coordinate their activities using the block wide synchronization function __syncthreads().
    11. Barrier Synchronization imposes execution constraints on threads within its scope. 
        1. Threads should execute in close proximity with each other to avoid execessively long waiting times.
        2. All the necessary resources to available for all the threads in a block.
        3. CUDA run time system satisfies this constraint by assigning execution resources to all the threads in a block as a unit.
        4. All the threads in a block should be assigned to the same SM.
    12. Block can begin execution when the cuda run time provides all the resources to the thread (all) in the block to complete execution.
    13. This ensures the time proximity of all threads in a block and prevent excessive or even indefinite waiting time during barrier synchronization.
    14. A group of thread blocks executing simultaneously is called wave. 
    15. Number of waves = Total number of thread blocks in the grid / No. of blocks that can execute simultaneously.
    16. Configure the numberof blocks in a grid as a multiple of the no. of blocks that can run simulataneously. No. of blocks that can run simultaneously depends on hardware resources available in the GPU.
