## CUDA Part - I

### What is a kernel?

1. Piece of device code which is executed by large number of threads.

1. Memory Address in device memory should not be dereferenced in the host code. Dereferencing a device global memory pointer in the host code can cause exceptions or other types of runtime errors.

2. Threads are collectively called grid.
3. when a program's host code calls a kernel , the CUDA runtime system launches a grid of thread that are organized into two level hierarchy.
    1. Each grid is organized as an array of thread blocks.
    2. Host code can specify the no. of threads in the block.
    3. Same kernel can be called with different number of threads at different part of the host code.
4. The no. of threads in a block is available in built-in variable 'blockDim'.Blocks are 3D structure. We can organize the threads in 3 dimensional inside block.
5. The choice of dimensionality for organizing threads usually reflect the dimensionality of the data.
6. Basically , threads are organized in blocks , blocks are organized in Grids.
7. CUDA gives you built in variable to access a particular thread in a Grid.
    1. threadIdx and blockIdx , threadIdx is index of the thread in a block and blockIdx is the index of the block in a grid.
    2. All the threads in the block has a common blockIdx.
    3. For calculation purpose - global index i = threadIdx.x + blockDim.x * blockIdx.x
8. If a function is declared in CUDA C kernel function as __global__ . The function is executed on device but can be called from host.
9. If a function is declared in CUDA C kernel function as __device__. The CUDA device function executes on CUDA device and can be called only from a kernel function or another device function.
10. Automatic variables are private to each thread.

### Multi- Dimensional Grids and Data

1. Block is a 3D array of threads.
2. Grid is a 3D array of blocks.
3. gridDim -> tells you the number of blocks. If the code is using gridDim.x , number of blocks in x direction. similarly we have gridDim.y and gridDim.z.
4. Point 3 is true for blockDim as well. It tells you the number of threads in a block . blockDim.x tells you the number of threads in x direciton. similarly , we have blockDim.y and blockDim.z.
5. All the blocks in the grid have the same size and dimensions.
6. The total size of the a block in current CUDA system is limited to 1024 threads.
7. Kernel_function <<< dimGrid , dimBlock >>> (...).

### Mapping Threads to Multi-Dimensional Data

1. The choice of 1D , 2D , 3D thread organization is usually based on the nature of the data.
2. Using a 2D grid that consist of 2D blocks is often convenient for processing the pixels.
3. Finding the coordinate if code is using a 2D grid.
    1. Vertical (row) coordinate = blockIdx.y * blockDim.y + threadIdx.y
    2. Horizontal (column) coordinate = blockIdx.x * blockDim.x + threadIdx.x

If we want to use each thread in a grid to calculate one output element of a vector addition , what would be the expression
for mapping the thread/block indices to the data index (i) in our kernel function?

### Exercise 4

#### Question
{: .exercise-question-heading}

For a vector addition , assume that the vector length is 8000 , each thread calculates one output element , and the thread block side is 1024 threads. The programmer configures the kernel call to have minimum number of thread blocks to cover all output elements. How many threads will be in the grid?

#### Answer
{: .exercise-answer-heading}

1. Constraint -> minimum number of thread blocks.
2. Use the full capacity of the block and that is 1024.
3. Number of blocks required = 8000/1024 = 7.8125 -> 8 blocks
4. 7 blocks will contain 1024 thread each which is 7168 and the last block will contain 1024 threads with 832 active and 192 inactive.
5. The answer is 8192.

### Question 3

#### Question
{: .exercise-question-heading}

Consider the following CUDA kernel and the corresponding host function that
calls it:

```cpp
/*
    __global__ void foo_kernel(float* a , float* b , unsigned int M , unsigned int N)
    {
        unsigned int row = blockIdx.y*blockDim.y + threadIdx.y;
        unsigned int col = blockIdx.x*blockDim.x + threadIdx.x;

        if(row < M && col < N)
        {
            b[row*N + col] = a[row*N + col]/2.1f + 4.8f;
        }
    }

    void foo(float* a_d , float* b_d)
    {
        unsigned int M = 150;
        unsigned int N = 300;
        dim3 bd(16 , 32);
        dim3 gd((N - 1)/16 + 1 , (M - 1)/32 + 1);
        foo_kernel < < < gd , bd > > >(a_d , b_d , M , N);
    }
*/
```

#### Answer
{: .exercise-answer-heading}

1. **What is the number of threads per block?**
    1. block_dimension = (16 , 32) -> Total Threads - 16 * 32 per block
    2. Number of threads in the grid -> threads in the block * blocks in the grid
    3. Threads in the block - 16 * 32 , Blocks in the grid -> 20 * 6 = 120 blocks
    4. Total Threads in the grid = 16 * 32 * 120 = 61440
    5. number of the blocks in the grid = 120
    6. number of threads that execute the line 05 - 150 * 300 = 45000 threads

### Question 4

Consider a two-dimensional matrix with a width of 400 and a height of 500. The matrix is stored as a one-dimensional array.
Specify the array index of the matrix element at row 20 and column 10:

<ol type="a">
  <li>If the matrix is stored in row major order.</li>
  <li>If the matrix is stored in column major order.</li>
</ol>

#### Answer
{: .exercise-answer-heading}

1. Total elements - 400 * 500 = 200000 elements - linearly placed
2. Array index of the element at row = 20 and column = 10
    1. If the matrix is stored in row major index
        1. each rows contains 400 elements - total Full rows covered = 19 . 19 * 400 elements
        2. Total elements covered = 19 * 400 + 10.
        3. array index = 7610 - 1 = 7609.
    2. If the matrix is stored in column major format
        1. we can solve this for row = 10 and column = 20 for width = 500 and height = 400
        2. Each row contains 500 elments - total Full rows covered = 9. 9 * 500 elements
        3. Total Element covered = 4500 elements + 20 = 4520 elements
        4. Array index = 4520 - 1 = 4519
